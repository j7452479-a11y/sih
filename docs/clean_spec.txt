1. Operational Context & Problem Formulation

1.1 The Domain & Problem Statement

Problem Statement ID: SIH26053.

Original Scope: Optimization of 3D LiDAR point clouds into 2.5D spatial maps for civilian autonomous electric vehicles (EVs).

Strategic Defense Pivot: Repurposed for military Manned-Unmanned Teaming (MUM-T). An airborne Unmanned Aerial Vehicle (UAV) and a terrestrial Unmanned Ground Vehicle (UGV) collaborate to map complex battlefield topographies and track hostiles on resource-constrained edge hardware.

1.2 The Edge Compute Bottleneck (SWaP Rationale)

Tactical drones operate under strict Size, Weight, and Power (SWaP) constraints.

Dense 3D Voxel Limitations: A standard uniform 3D voxel grid over a 100\text{ m} \times 100\text{ m} \times 20\text{ m} operational envelope at a fine 5\text{ cm} resolution yields: \left(\frac{100}{0.05}\right) \times \left(\frac{100}{0.05}\right) \times \left(\frac{20}{0.05}\right) = 2000 \times 2000 \times 400 = 1.6 \times 10^9 \text{ voxels} At 1 byte per voxel (occupancy only), this consumes 1.6\text{ GB} of static RAM per frame buffer, causing instant cache thrashing, high latency, and thermal throttling on embedded hardware (e.g., NVIDIA Jetson Orin Nano / Xavier NX).

Standard 2D Grid Failure: Collapsing the world into a single 2D grid removes volumetric elevation entirely, blinding operators to sheer drop-offs, elevated firing positions, and structural walls.

The Engine Solution: A 4-Tier Foveated Multi-Level Surface (MLS) representation that preserves multi-layered vertical geometry (overhangs, underpasses) while compressing the processing payload to < 20\text{ MB} per frame, running deterministically at \ge 20\text{ Hz}.

2.1 The UDP Synchronization Protocol

Raw UDP does not guarantee packet arrival order or delivery. Feeding out-of-sync frames into an SE(3) transformation warps the fused map geometry.

Binary Payload Structure: Every payload transmitted from UE5 must begin with an explicit 21-byte header:[uint32: frame_id] (4 bytes)[float64: unix_timestamp] (8 bytes)[uint8: sensor_type] (1 byte: 0x01 = UAV, 0x02 = UGV, 0x03 = UWB_RADAR)[uint32: point_count] (4 bytes)[uint32: payload_checksum] (4 bytes)Followed by: [point_count * 3 * float32 (X, Y, Z coordinates)]

Temporal Jitter Buffer: Machine 2 maintains a ring buffer with a dynamic window of \Delta t_{\text{max}} = 50\text{ ms}.

A fusion step executes only when a UAV packet and a UGV packet satisfy: \vert{}t_{\text{uav}} - t_{\text{ugv}}\vert{} \le 25\text{ ms} \quad \text{or} \quad \text{frame\_id}_{\text{uav}} == \text{frame\_id}_{\text{ugv}}

If a packet arrives past the temporal window, it is dropped. Spatial alignment is never calculated against stale temporal data.

3. Coordinate Registration & Spatial Compression Engine

3.1 Accelerated SE(3) Transformation & Registration

The UAV operates in local body frame \mathcal{F}_{\text{uav}}, and the UGV operates in local frame \mathcal{F}_{\text{ugv}}. To combine these streams into a global coordinate frame \mathcal{F}_{\text{world}}, the system applies an SE(3) Euclidean transformation:

\mathbf{p}_{\text{world}} = \mathbf{R}_{t} \cdot \mathbf{p}_{\text{local}} + \mathbf{t}_{t}

Where \mathbf{R} \in SO(3) is the rotation matrix derived from the platform's onboard IMU/EKF, and \mathbf{t} \in \mathbb{R}^3 is the translation vector derived from RTK-GPS/visual odometry.

ALGORITHM: Accelerated Point-to-Plane ICP RegistrationInput: Source Points P_src (UGV), Target Points P_tgt (UAV Prior), Initial Transform T_0Output: Optimized Transform T_optimal1. Insert P_tgt into a 3D Voxel Hash Grid (cell size = delta_tier).2. For each iteration k in 1 to K_max:     a. Query corresponding points in P_tgt for each point in P_src via Hash lookup:        - Query cost is O(1) average per point; total correspondence search is O(N).     b. Filter correspondences based on Euclidean distance threshold d_max and normal angle.     c. Solve the linearized point-to-plane objective via Cholesky decomposition:        arg min_{T} sum_i || (T * p_src,i - q_tgt,i) . n_tgt,i ||^2     d. Update T_k. If ||T_k - T_{k-1}|| < epsilon, break.3. Return T_optimal.

Complexity: Avoids the naive brute-force all-pairs correspondence search of O(N \cdot M) or O(N^2). Spatial hashing / KD-tree bounding guarantees O(N \log M) execution.

3.3 The Capped Multi-Level Surface (MLS) Map

A single (z_{\max}, z_{\min}) pair creates a continuous vertical pillar, falsely marking the empty space beneath a bridge or roof as a solid obstacle.

The engine implements a Capped Multi-Level Surface (MLS) array. Each discrete (x, y) coordinate cell maintains an ordered list of up to K=3 discrete vertical surface intervals.

       CELL COLUMN ARCHITECTURE: cell(x, y)              +------------------------------------+  <- z_high_2 (Bridge Roof: 5.2m)       | Interval 2: Solid Concrete Deck    |       +------------------------------------+  <- z_low_2  (Bridge Underside: 4.8m)       |                                    |       |       [CLEARED VOID SPACE]         |  <- Preserved by UGV line of sight       |       (Traversable for Units)      |       |                                    |       +------------------------------------+  <- z_high_1 (Road Surface: 0.2m)       | Interval 1: Asphalt Substrate      |       +------------------------------------+  <- z_low_1  (Ground Base: 0.0m)

Interval Allocation & Merging Logic:

Each cell stores a fixed-capacity struct:

struct MLSInterval {    float z_low;    float z_high;    uint16_t point_density;    uint8_t semantic_class; // 0=Ground, 1=Obstacle, 2=Target};struct MLSCell {    uint8_t count; // Number of active intervals (0 <= count <= 3)    MLSInterval intervals[3];};

Ingestion: For an incoming point (x_p, y_p, z_p), determine its spatial grid cell (i_x, i_y) = (\lfloor x_p/\Delta \rfloor, \lfloor y_p/\Delta \rfloor).

Interval Search: Compare z_p against all existing active intervals k \in [0, \text{count}-1]:

If \vert{}z_p - z_{\text{high}, k}\vert{} \le \tau_{\text{merge}} or \vert{}z_p - z_{\text{low}, k}\vert{} \le \tau_{\text{merge}} (where \tau_{\text{merge}} = 10\text{ cm}): z_{\text{low}, k} = \min(z_{\text{low}, k}, z_p), \quad z_{\text{high}, k} = \max(z_{\text{high}, k}, z_p) Increment point_density.

If z_p does not fall within \tau_{\text{merge}} of any interval, and \text{count} < 3: Instantiate a new interval: \text{intervals}[\text{count}] = \{z_{\text{low}}: z_p, \, z_{\text{high}}: z_p, \, \text{point\_density}: 1\} Sort the interval array such that z_{\text{low}, k} < z_{\text{low}, k+1}, and increment count.

If \text{count} == 3 and a new point cannot be merged, merge the two intervals separated by the smallest vertical distance to prevent silent data drop.

4. Kinematic Multi-Target Tracking (MTT) Pipeline

The Multi-Target Tracking system converts spatial clusters into persistent tactical tracks, executing four discrete steps sequentially on every frame update.

Raw Multi-Modal Data        |        v[Step 1: Tier-Aware Clustering]   - Dynamic eps_k = c * Delta_k (Solves non-uniform foveated density)        |        v (Centroids z_k)[Step 2: Kalman Prediction & Validation Gating]  - Advance state x_{k|k-1}  - Compute Mahalanobis Gate d_M^2 <= gamma        |        v[Step 3: Global Data Association]  - Hungarian Algorithm on Cost Matrix C_ij        |        v[Step 4: Kinematic State Update & Track Lifecycle]  - Match -> Kalman Update  - Unmatched Detection -> Spawn Tentative Track  - Unmatched Track -> Coast / Increment Miss Counter

4.1 Step 1: Tier-Aware Density Clustering

Because point density drops systematically across the foveated tiers, standard DBSCAN with a single global \epsilon fails. It over-merges near-field points into single monolithic blocks and fragments distant targets into noise.

Dynamic Radius Calibration: Clustering is executed per tier k \in \{1, 2, 3, 4\}, with \epsilon_k dynamically scaled proportional to grid resolution \Delta_k: \epsilon_k = 1.5 \cdot \Delta_k, \quad \text{MinPts} = 5

Tier 1 (5\text{ cm} resolution): \epsilon_1 = 7.5\text{ cm}

Tier 2 (10\text{ cm} resolution): \epsilon_2 = 15.0\text{ cm}

Tier 3 (20\text{ cm} resolution): \epsilon_3 = 30.0\text{ cm}

Tier 4 (50\text{ cm} resolution): \epsilon_4 = 75.0\text{ cm}

Centroid Extraction: For every valid cluster \mathcal{C}_j, compute the 3D spatial centroid \mathbf{z}_j = [x_j, y_j]^T representing the detection measurement vector.

4.2 Step 2: Kalman Prediction & Validation Gating

Each target track is modeled via a 2D Constant Velocity (CV) kinematic state vector:

\mathbf{x}_k = \begin{bmatrix} x \\ y \\ \dot{x} \\ \dot{y} \end{bmatrix}, \quad \mathbf{F} = \begin{bmatrix} 1 & 0 & \Delta t & 0 \\ 0 & 1 & 0 & \Delta t \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{bmatrix}, \quad \mathbf{H} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \end{bmatrix}

State Prediction: \hat{\mathbf{x}}_{k\vert{}k-1} = \mathbf{F} \hat{\mathbf{x}}_{k-1\vert{}k-1} \mathbf{P}_{k\vert{}k-1} = \mathbf{F} \mathbf{P}_{k-1\vert{}k-1} \mathbf{F}^T + \mathbf{Q} Where \mathbf{Q} is the discrete process noise covariance matrix parameterized by continuous spectral density q: \mathbf{Q} = q \begin{bmatrix} \frac{\Delta t^3}{3} & 0 & \frac{\Delta t^2}{2} & 0 \\ 0 & \frac{\Delta t^3}{3} & 0 & \frac{\Delta t^2}{2} \\ \frac{\Delta t^2}{2} & 0 & \Delta t & 0 \\ 0 & \frac{\Delta t^2}{2} & 0 & \Delta t \end{bmatrix}

Validation Gating (Mahalanobis Distance): For track i and detection j, the measurement residual is: \mathbf{y}_{ij} = \mathbf{z}_j - \mathbf{H} \hat{\mathbf{x}}_{k\vert{}k-1}^{(i)} The residual covariance is: \mathbf{S}_i = \mathbf{H} \mathbf{P}_{k\vert{}k-1}^{(i)} \mathbf{H}^T + \mathbf{R} The squared Mahalanobis distance is evaluated against gate threshold \gamma = 9.21 (corresponding to a 99% validation region for a 2-DOF \chi^2 distribution): d_{M, ij}^2 = \mathbf{y}_{ij}^T \mathbf{S}_i^{-1} \mathbf{y}_{ij} \le \gamma If d_{M, ij}^2 > \gamma, assignment is strictly prohibited (C_{ij} = \infty).

4.3 Step 3: Global Data Association (Hungarian Algorithm)

To eliminate identity switches when targets cross paths or execute tight maneuvers, assignments are solved globally across all active tracks and detections.

Cost Matrix Construction: An assignment matrix \mathbf{C} \in \mathbb{R}^{N \times M} (where N is the number of active tracks and M is the number of detections) is constructed: C_{ij} = \begin{cases} d_{M, ij}^2 & \text{if } d_{M, ij}^2 \le \gamma \\ \infty & \text{if } d_{M, ij}^2 > \gamma \end{cases}

Global Optimization: Solve using the Munkres/Hungarian algorithm in O(\max(N, M)^3) time: \min \sum_{i=1}^N \sum_{j=1}^M C_{ij} X_{ij}, \quad \text{subject to} \sum_{i} X_{ij} \le 1, \,\, \sum_{j} X_{ij} \le 1, \,\, X_{ij} \in \{0, 1\}

4.4 Step 4: State Update & Lifecycle State Machine

Matched Tracks: Updated via standard Kalman equations: \mathbf{K} = \mathbf{P}_{k\vert{}k-1} \mathbf{H}^T \mathbf{S}^{-1} \hat{\mathbf{x}}_{k\vert{}k} = \hat{\mathbf{x}}_{k\vert{}k-1} + \mathbf{K} \mathbf{y} \mathbf{P}_{k\vert{}k} = (\mathbf{I} - \mathbf{K} \mathbf{H}) \mathbf{P}_{k\vert{}k-1}

Track Lifecycle Rules:

Track Birth: An unmatched detection spawns a TENTATIVE track.

Track Confirmation: A TENTATIVE track must achieve N=3 consecutive frame associations to graduate to CONFIRMED.

Coasting (Occlusion): When a CONFIRMED track misses associations, its state propagates using \hat{\mathbf{x}}_{k\vert{}k-1} alone, and an internal counter miss_count increments.

Track Death: If miss_count exceeds M=5 consecutive frames (\sim 250\text{ ms} at 20\text{ Hz}), the track is purged from memory.

5. Synthetic UWB Radar Injection & Provenance Tracking

5.1 Tactical Target Designator (UI Measurement Engine)

The operator uses the C2 dashboard to draw a bounding rectangle [x_{\min}, x_{\max}, y_{\min}, y_{\max}] across a structural footprint. The engine calculates precise structural dimensions directly from the MLS data:

\text{Width} = \vert{}x_{\max} - x_{\min}\vert{}, \quad \text{Length} = \vert{}y_{\max} - y_{\min}\vert{} \text{Height} = \max_{(x, y) \in \text{ROI}} \left( z_{\text{high}} \right) - \min_{(x, y) \in \text{ROI}} \left( z_{\text{low}} \right)

5.2 Synthetic Radar Injection Pipeline

When the operator clicks [INITIATE UWB PENETRATION], the system runs the following:

Ceiling Culling: Suppresses the highest MLS interval (z \ge 2.5\text{ m}) across the selected bounding box, rendering the roof translucent.

RF Point Injection: Pulls pre-calculated synthetic Ultra-Wideband (UWB) reflections from UDP Port 5003, scattering the points using an additive Gaussian noise model to mimic radar multipath: \mathbf{p}_{\text{radar}} \sim \mathcal{N}(\mathbf{p}_{\text{truth}}, \mathbf{\Sigma}_{\text{multipath}}), \quad \mathbf{\Sigma} = \text{diag}(0.15\text{ m}, 0.15\text{ m}, 0.05\text{ m})

For every target track \mathbf{x}_{\text{target}} and friendly soldier \mathbf{x}_{\text{unit}}:

\mathcal{D} = \Vert{}\mathbf{x}_{\text{target}} - \mathbf{x}_{\text{unit}}\Vert{}_2

If \mathcal{D} \le 50\text{ m}: Soldier unit receives full kinematic telemetry at 20\text{ Hz}.

If \mathcal{D} > 50\text{ m}: Soldier unit receives downsampled macro-status updates at 0.5\text{ Hz}.

6.3 Decoupled C2 Dashboard Architecture

To eliminate the synchronous script re-execution lag native to standard Streamlit loops, the interface is split:

Operational Backbone (FastAPI): Exposes an asynchronous WebSocket server on ws://127.0.0.1:8000/ws/tactical_feed streaming track updates at 20\text{ Hz}.

Live Tactical Map Client (React / HTML5 Canvas or Dash with dcc.Interval): Ingests the WebSocket feed, rendering the foveated MLS layers, target vectors, and translucent radar volumes without UI blocking.

Telemetry & Benchmark Dashboard (Streamlit): Runs asynchronously on a secondary port strictly for static verification tasks:

Plotting memory footprint benchmarks (Raw Point Cloud vs. Sparse MLS).

System health logs, dropped-frame telemetry, and network latency monitoring.
